﻿﻿﻿﻿﻿# 职顾问 · offer 之前，先查这家公司 🔍

一个面向求职者的**企业公开记录调查工具**。输入公司名，就能看到它有没有欠薪、社保欠缴、违规收费、被执行等**官方公开记录**；每条结论都能点回原文，并附带抓取时间与页面快照哈希。

不做企业评分，不做黑名单，不收费删帖。**查不到，不代表安全。**

> 本项目用于学习与交流。所有结论均来自官方公开渠道的二次整理，不替代官方查询，也不构成法律意见。

## ✨ 功能特性

### 🔎 企业公开记录检索

- **多种查法**：公司全称、简称、统一社会信用代码均可查询，支持拼音首字母
- **同名企业区分**：按「信用代码优先 + 省市地区」区分同名主体，避免把两家公司混成一家
- **主体与记录同页**：企业主体信息、风险信号、来源集中在同一页，不用在多个政府网站之间来回跳转
- **当前数据**：730 家企业主体、686 条已核验公开信号，覆盖 31 个省级行政区的人社部门公告
- **覆盖进度**：已接入 31 个省级行政区，实现省级行政区全覆盖；所有结论均来自官方主动公开公告，覆盖率在收录请求页公开

### 🧾 可核验的证据链

每条记录都带完整血缘，而不是一张截图：

| 字段 | 作用 |
|------|------|
| `sourceUrl` / `sourceTitle` | 原始公告地址与标题 |
| `sourcePublishedAt` / `fetchedAt` | 官方公布时间与我们的抓取时间 |
| `snapshotHash` / `snapshotPath` | 抓取快照的 sha256 与只读快照路径 |
| `ingestRunId` / `parserVersion` | 由哪次采集运行、哪个解析器版本产生 |
| `inputsHash` / `rulesVersion` / `templateVersion` | 报告由哪些输入、哪版规则与模板生成 |

- 点开页面上的任意数字，弹出「证据与来源」面板，可查看来源、公布时间、快照哈希并打开抓取快照
- 来源被撤下或发现错误时，可按来源批量撤回信号，并写入 `SignalAuditEvent` 审计记录
- 任一输入变化都会生成新的报告缓存键，避免继续返回旧结论

### ⚖️ 规则判定，措辞可复算

- **判定与表达分离**：是否命中风险由 `rules/rules.json` 中的 7 条规则（R01–R07）决定
- **模板默认**：公开站点默认用模板生成措辞，日期与金额格式全站统一、可复算
- **模型可选**：配置模型 Key 后才启用润色，模型仍不提供数字、不新增结论，失败自动回落模板
- **报告可复算**：规则版本由规则文件内容哈希得出，改规则不会返回旧报告

### 🛡️ 企业申诉与更正

- 企业可提交申诉，选择事实错误、信息过期、缺少上下文、主体错误等类别，并附证明材料链接
- 申诉有完整状态流转（`open → reviewing → resolved / rejected`）与处理流水，历史不被覆盖
- 核实后可更正或撤回记录，对外的更正说明展示在报告页
- 未收录企业同样可以提交，不强制关联已有主体

### 💬 匿名面试反馈

- 只允许结构化选项（面试轮次、出结果时长、是否询问隐私、是否有测试任务等），**不收集自由文本**
- 匿名标识使用加盐哈希，不保存明文身份
- 汇总后以区间分布展示，不作为企业评分

### 🧭 查不到时的兜底

- 未收录企业不会给空白页，而是给出**官方直查入口**：国家企业信用信息公示系统、信用中国、执行信息公开网
- 提供收录请求入口，并明确写出当前覆盖范围与数据来源
- 首页与报告页都明确提示：**查不到，不等于安全**

### 🔐 隐私与安全

- 全站不需要登录即可查询，不设付费墙
- 管理后台独立登录：密码 + 会话 nonce 入库，退出即吊销；修改密码会让所有旧会话失效
- 匿名反馈只存加盐哈希；申诉联系方式仅用于核实
- 所有写接口带速率限制与参数校验（Zod）

## 💡 设计理念

### 为什么只做公开记录

个人开发者拿不到稳定的商业数据库接口，直接抓取部分官方系统也存在合规风险。与其做一个"看起来数据很多、实际无法核验"的产品，不如只做**能稳定获取、能点回原文**的那一部分：地方人社部门的劳动用工公告。数据量小，但每一条都站得住。

### 为什么不做评分和黑名单

- **评分会把复杂事实压成一个数字**，求职者反而看不到具体发生了什么
- **黑名单容易误伤**：同名企业、已履行完毕的案件、已更正的记录，都可能被永久贴上标签
- 所以这里只呈现**有时间、有来源、有阶段**的记录，把判断权交还给用户

### 为什么每条结论都要能点回原文

截图可以伪造，链接会失效，网页会被修改。证据链要回答的不是"你有没有证据"，而是"**这条结论是怎么来的、什么时候抓的、现在还能不能核验**"。所以我们同时保存原文链接、抓取时间与快照哈希，并明确说明哈希不能防止原网页后续被修改或删除。

### 为什么强调"查不到不代表安全"

未收录有两种可能：这家公司确实没有问题，或者我们还没采到。把后者说成前者，就是在制造虚假的安全感。所以覆盖范围、数据来源和更新时间都写在明面上。

## 💻 系统要求

- **Node.js** 20+（生产运行时为 Node.js 20）
- **pnpm** 10.33.0
- **PostgreSQL** 18（生产使用 Neon PostgreSQL）
- **操作系统**：Windows / macOS / Linux 均可；仓库内提供 Windows 一键启动脚本
- **可选**：一个兼容 OpenAI 协议的大模型 API（不配置时报告自动回落模板）

## 🚀 快速开始

### 1. 克隆项目

```bash
git clone https://github.com/KarryGuo/JobConsultant.git
cd JobConsultant
```

### 2. 安装依赖

```bash
pnpm install
```

### 3. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，至少填好 `DATABASE_URL`；后台密码、匿名盐、模型 Key 按需填写。

### 4. 初始化数据库

```bash
pnpm db:generate
pnpm exec prisma migrate deploy
pnpm seed:sources
pnpm import:data
```

### 5. 启动

```bash
pnpm dev
```

打开 `http://localhost:3000`。首页开场动画可点「跳过」或按 Esc。

### 6. Windows 一键启动（可选）

```bash
pnpm start:local
```

脚本会依次完成：启动本地 PostgreSQL（5433）→ 建库 → 迁移 → 种子与导入 → 构建 → 启动生产服务。数据目录与 PostgreSQL 路径可用 `ZGW_PG_BIN`、`ZGW_PG_DATA` 覆盖。

### 7. 预热报告（可选）

```bash
pnpm prewarm:reports
```

提前为已收录企业生成报告，避免评委或用户首次访问时等待报告生成。

## 🏗️ 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│                         数据来源层                            │
│  地方人社部门公告（陕西 / 河南 / 安徽 / 湖北 / 福建 …）        │
│  官方直查入口：企业信用信息公示系统 / 信用中国 / 执行信息公开网 │
└───────────────────────────┬──────────────────────────────────┘
                            │ 采集
┌───────────────────────────▼──────────────────────────────────┐
│                         采集与解析层                          │
│  ingest-announcements  →  原始快照（sha256） + IngestRun      │
│  按省份解析器          →  结构化 Signal（parserVersion）      │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│                          判定层                               │
│  rules.json（R01–R07）→ Hit / 结论 / 建议问的问题             │
│  命中结果与 signalIds 强绑定，空引用拒绝入库                   │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│                          表达层                               │
│  模板措辞（可复算）→ 可选模型润色，失败回落模板                │
│  Report：inputsHash / rulesVersion / templateVersion          │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│                          展示层                               │
│  Next.js App Router：企业档案 / 证据面板 / 申诉 / 后台         │
│  SEO：sitemap、robots、canonical、Open Graph、JSON-LD         │
└──────────────────────────────────────────────────────────────┘
```

**关键原则**：判定在规则层完成，默认措辞由模板生成；配置模型后模型也只是把事实写成句子，不产生数字。证据在采集层固化，展示层只能引用、不能改写。

## 📊 数据模型

| 模型 | 作用 |
|------|------|
| `Company` | 企业主体，`normalized + regionKey` 唯一，信用代码优先匹配 |
| `Signal` | 单条公开记录，来源、时间、快照哈希、血缘字段为必填 |
| `IngestRun` | 每次采集运行，成功/失败都记录，用于解释数据为何未更新 |
| `SignalAuditEvent` | 信号审计流水：复核、作废、更正、来源批量撤回 |
| `Report` | 报告缓存，含结论、要点、数据截止时间与版本哈希 |
| `InterviewFeedback` | 匿名面试反馈，仅结构化选项 + 加盐哈希 |
| `ReportFeedback` | 报告底部的决策反馈（投递/放弃 + 固定原因） |
| `JdPhrase` | JD 话术库，用于解释招聘措辞 |
| `AppealRequest` | 企业申诉/更正申请，支持未收录企业提交 |
| `AppealEvent` | 申诉处理流水，只追加不覆盖 |
| `AdminSession` | 后台会话，nonce 入库，可吊销 |
| `SourceHealth` | 来源健康：最近状态、内容指纹、连续失败次数 |
| `SourceRegistry` | 来源注册表：分类、等级、抓取方式、复核周期 |

## 📖 使用说明

### 主要页面

| 路径 | 说明 |
|------|------|
| `/` | 首页：搜索、示例企业、收录统计、调查方法 |
| `/companies` | 已收录企业列表 |
| `/company/[id]` | 企业档案：结论、记录、证据面板、官方直查入口、申诉入口 |
| `/search?q=` | 搜索结果；唯一命中直接跳转企业页，多主体返回候选 |
| `/coverage` | 覆盖范围与收录请求 |
| `/about` | 产品说明、调查方法与数据来源 |
| `/privacy` | 隐私说明 |
| `/appeal` `/appeal/status` | 企业申诉提交与进度查询 |
| `/feedback/[companyId]` | 匿名面试反馈 |
| `/admin` | 后台：申诉审核、信号复核、来源健康 |

### 体验路径

1. 打开首页，搜索「知途」（或点示例词：知途 / 中铁十八局 / 中建七局）
2. 进入企业档案，阅读结论与公开记录
3. 点整段结论，打开「证据与来源」，查看来源、公布时间、快照哈希
4. 搜一家未收录企业，查看官方直查入口与收录请求
5. 打开企业申诉入口，了解记录如何被更正或撤回

### 主要接口

| 接口 | 说明 |
|------|------|
| `GET /api/health` | 健康检查，返回数据库连通状态 |
| `GET /api/search` | 企业搜索 |
| `GET /api/search/suggest` | 搜索联想 |
| `POST /api/report` | 生成或读取报告 |
| `GET /api/evidence/[signalId]` | 证据详情与只读快照 |
| `POST /api/appeal` / `GET /api/appeal/status` | 申诉提交与查询 |
| `POST /api/interview-feedback` | 匿名面试反馈 |
| `POST /api/report-feedback` | 报告决策反馈 |
| `/api/admin/*` | 后台登录、申诉处理、信号复核、来源检查 |

## 📊 数据来源与边界

- **用于自动结论的来源**：各地人社部门主动公开的劳动用工公告（当前覆盖 31 个省级行政区，完整清单见收录请求页的覆盖地图）
- **仅作为官方直查入口**：国家企业信用信息公示系统、信用中国、中国执行信息公开网
- **更新与复核**：每条来源有复核周期，超过 35 天没有新公告会在来源健康检查中告警
- **能力边界**：
  - 这不是全国企业库，未收录企业请通过收录请求提交
  - 抓取快照哈希只能证明记录在入库时存在，不能防止原始网页后续被修改或删除
  - 记录可能不完整，涉及法律判断时请以官方原文为准
  - **查不到，不代表安全**
